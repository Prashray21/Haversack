# Coding rules

## TypeScript

- Strict mode, ESM (`"type": "module"`), Node >= 20. Import other workspace
  files with the `.js` extension (tsc NodeNext).
- No new dependency without asking first (name, size, why). Zero-dependency
  implementations are preferred where the stdlib suffices.
- Library and command code never write to `console` — commands receive
  `stdout`/`stderr` as injected parameters. The single allowed exception is the
  top-level catch in `packages/cli/src/main.ts`.
- Pure functions where the design allows: adapters and static checks must stay
  free of fs, git, network, and clock access.

## Tests

- Every adapter, parser, and command gets tests in the owning package's
  `test/` directory (vitest). A bug fix lands with a failing regression test
  first, a root-cause fix, and a guard against the whole class of bug.
- Fixture files are committed with LF endings and no BOM.

## Files and formatting

- LF line endings, UTF-8 without BOM. Files generated by `runtime sync` are
  pinned to LF in `.gitattributes` — never hand-edit them.
- Check ids, project identifiers, and rule slugs are kebab-case.

## Compatibility

- Windows is a first-class platform: no POSIX-only assumptions in source,
  forward-slash globs in config, 8.3-safe repo-root detection.
