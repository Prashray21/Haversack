# Security Policy

## Supported versions

The project is pre-1.0: only the latest `main` branch and the most recent release tag receive security fixes.

## Reporting a vulnerability

Use GitHub's **private vulnerability reporting** (Security tab → "Report a vulnerability") on this repository. Please do not open a public issue for anything you believe is exploitable.

- Triage target: **72 hours**.
- Include reproduction steps, affected command, and (if possible) a minimal repo that triggers it.

## Design boundaries you can rely on

- Generated files always carry the `GENERATED BY RUNTIME — DO NOT EDIT` header; hand edits are reported as drift, never silently overwritten.
- Secret scanning runs on `sync` and `check`; findings are always redacted — the matched value is never printed, logged, or stored.
- API keys are read from environment variables only; they are never written to generated files, logs, or the manifest.
- The LLM judge (when enabled) receives repo content as delimited, untrusted data, returns structured verdicts only, and has no tool access (PRD §10).

## Known limitations

- Release binaries are unsigned on Windows and Linux (Windows SmartScreen will warn on first run); macOS binaries carry an **ad-hoc** signature only (required to execute on Apple Silicon), not a Developer-ID/possibly-notarized signature.
- `runtime check` runs arbitrary regexes from `project.yaml` — that file is part of your repo and subject to your own review controls.

## Dependency posture

Lockfile is committed (`pnpm-lock.yaml`), installs use `--frozen-lockfile` in CI, and a dependency license report is generated in `docs/dependency-licenses.md`.
